# Décisions

Une ligne par arbitrage : date, choix, pourquoi, alternative écartée.

- 2026-11-12 — Nom : blockquilt (des blocs cousus en un seul texte, libre sur npm et GitHub). Écartés : blockpen, blockquill, blockstitch, blocmark.
- 2026-11-12 — Extraction telle quelle de l'éditeur de rubrique d'easyHomeGuide (commit `07ec88a`) ; easyHomeGuide garde sa copie. Écarté : le hub stackfast (plus tard, peut-être).
- 2026-11-12 — Docker : `node:22-alpine` pour la démo, `node:22-slim` + Chromium (paquet Debian) pour la validation. Aucune dépendance npm : serveur avec `node:http`, multipart lu par `Request.formData()`, CDP par le `WebSocket` intégré à Node 22. Écartés : Puppeteer/Playwright (dépendances lourdes), une démo sans serveur (enregistrer et photo non testables).
- 2026-11-12 — Polices Plus Jakarta Sans et Newsreader livrées avec leur licence SIL OFL 1.1 (`fonts/OFL-*.txt`), le dépôt étant public.
- 2026-11-12 — Licence MIT pour le code (réutilisation libre, le but est l'intégration dans d'autres projets). Les polices gardent la SIL OFL 1.1.
- 2026-11-12 — Visualisation : rendu invité dans le noyau (`Blocks.toHtml`, fonction pure) avec les teintes de `Blocks.TYPES`, utilisé par le serveur de démo et par l'éditeur quand `data-preview` est absent. easyHomeGuide garde son rendu PHP (`markdown.php`, variables du homebook). Écartés : une dépendance Markdown npm (le projet n'en a aucune), recopier le rendu PHP en JS (deux lectures du Markdown au lieu d'une).
- 2026-11-12 — Phase 1 : retrait de `app.js`, `reference/`, `docs/`, de la fausse IA locale (expressions régulières) et du type « audio » ; les feuilles `<dialog>` sont gérées par `blockquilt.js`. Préfixe `bq` à la place de `ehg`. Écarté : garder `app.js` pour 25 lignes utiles.
- 2026-11-12 — Phase 2 : registre `Blocks.register(type, def)` ; un bloc est lu par le premier type (ordre d'enregistrement) dont l'écriture redonne le même texte, sinon `raw`. Noyau (`blockquilt.js`, utilisable sous Node) et écran (`blockquilt-editor.js`, ajoute `edit`/`read`) séparés. Un type sans carte d'édition propre est édité comme texte source. Écarté : un `switch` par fonction (sept endroits à toucher par type).
- 2026-11-12 — Phase 3 : format pivot unique (FORMAT.md) : frontmatter `clé: valeur` à plat, encadrés `> [!type]` (info, tip, success, warning, danger) en minuscules, `##`/`###`, `---`, code clôturé. Aucun code de lecture de l'ancien format (`## 🏡 Titre`, `> 💡`, `:::sensible`) : il tombe en H2, citation ou bloc source, sans perte. Écarté : `[!TIP]` en majuscules (reste un bloc source, signalé par `lint`) pour garder une seule écriture.
- 2026-11-12 — Rendu publié : `<article class="bq-content">`, `<h1>` depuis le frontmatter (option `title: false`), classes `bq-*` et feuille `blockquilt-content.css` écrite à la main (couleurs en variables CSS). Un bloc source est rendu en `<pre class="bq-raw">`, texte échappé, jamais interprété. Écarté : interpréter les tableaux ou le HTML d'un bloc source.
- 2026-11-12 — Photo : `![légende](media/<id>)` ou `https://…` (modèle `src`). Légende = `alt` + `<figcaption>`. Code en ligne `` `x` `` reconnu dans le texte. Groupe `structure` (ligne, code) ajouté à `text` et `media` pour le menu d'ajout.
- 2026-11-12 — Phase 4 : `Blockquilt.mount(element, options)` fabrique tout l'écran (en-tête, cartes, feuilles) ; icônes SVG en ligne (tracés Lucide) et aucun attribut `id` : plusieurs éditeurs cohabitent dans une page. Tous les écouteurs passent par un `AbortController` : `destroy()` les retire d'un coup. Échanges : `fields` (ex. jeton CSRF) + `text` (enregistrer, aperçu) ou `photo` (envoi, réponse `{ id }` ou `{ src }`). Écarté : garder le HTML de l'éditeur dans la page hôte (85 lignes à recopier).
- 2026-11-12 — Carte de bloc : badge de type (liste de conversion) à gauche, poignée et menu « ⋯ » à droite ; monter, descendre, dupliquer et supprimer passent dans le menu. Boutons « Insérer » et « Fusionner » avec une cible de 44 px mais une pastille de 28 px. Écarté : rail latéral et corbeille en bas de carte (vide sous les titres).
- 2026-11-12 — Phase 5 : historique de 50 instantanés (texte complet + place du bloc actif), pris avant et après chaque action de structure et après 1 s sans frappe ; pendant une frappe, Ctrl+Z reste au navigateur. Écarté : 10 instantanés (trop court dès qu'on réorganise), un historique par opération (plus de code, plus de cas).
- 2026-11-12 — Barre de mise en forme fixe et centrée (bas de l'écran visible au téléphone, sous l'en-tête à l'ordinateur), ouverte par sélection, double clic, appui long ou clic droit, fermée à la perte du focus ; elle ne garde que le style et « scinder ». Les actions sur le bloc vont dans le menu « ⋯ ». Écarté : une barre qui suit la sélection, un menu unique chargé.
- 2026-11-12 — Glisser-déposer : l'ordre ne change qu'au lâcher ; trait bleu de 3 px, copie qui suit le doigt, Échap annule. Plein écran : un `<dialog>` modal de 100dvw × 100dvh (éditeur entier déplacé dedans, ou bloc seul), plus `requestFullscreen()` quand il est permis. Copier / coller : Markdown du bloc dans le presse-papiers (copie interne en secours), collage découpé par `Blocks.parse`.
- 2026-11-12 — Phase 6 : `emoji.json` (1 898 emoji, 121 Kio) fabriqué une fois par `dev/build-emoji.mjs` depuis Unicode `emoji-test.txt` 15.1 et CLDR français, commité ; teintes de peau écartées (forme de base seulement) pour tenir sous 150 ko. Chargé au premier usage du sélecteur, à côté de `blockquilt-editor.js` (option `emojiUrl`). Un seul sélecteur pour l'icône du document, l'icône d'un encadré et l'insertion dans le texte ; « récents » en `localStorage`. Écarté : une liste d'emoji en dur dans le JS (poids chargé à chaque page).
- 2026-11-12 — Phase 7 : carrousel `:::carousel` (une ligne `![légende](src)` par photo, `:::`). Rendu sans JavaScript : piste `scroll-snap` horizontale, une `<figure>` par photo, points de repère décoratifs (`aria-hidden`). Édition : vignettes, légende, déplacement gauche / droite, retrait, ajout de plusieurs fichiers à la fois. Colonnes : hors périmètre (`:::columns` reste un bloc source). Écarté : points cliquables par ancres (identifiants dans la page, saut vertical).
- 2026-11-12 — Phase 8 : bloc `:::html`, source gardé tel quel, rendu toujours filtré par `Blocks.sanitize` (sans DOM, tourne sous Node). Liste blanche figée : `div span p br hr h2 h3 h4 ul ol li strong em u mark small a img figure figcaption table thead tbody tr th td` ; `class` partout, `href` http(s)/mailto/tel sur `a`, `src` (`media/…` ou https), `alt`, `width`, `height` sur `img`, `colspan`/`rowspan` sur `th`/`td`. Les entités et caractères invisibles sont décodés avant de vérifier une adresse ; `script`, `style`, `svg`, `iframe`… sont retirés avec leur contenu ; les balises restées ouvertes sont fermées. Bloc absent du menu d'ajout sans `html: true` (un bloc existant s'édite alors comme texte source). Tailwind : seules les classes du CSS de l'hôte ont un effet. Écarté : `DOMParser` (absent sous Node), `style=` et `id` (trop de surface).
- 2026-11-12 — Phase 9 : IA par un seul échange fourni par l'hôte (`aiUrl`) : `POST` `scope`, `instruction`, `text`, `block` → `{ markdown }`. L'éditeur n'appelle aucun modèle et ne contient aucune clé ; sans `aiUrl`, aucun bouton IA. La réponse passe par `Blocks.lint` ; avec une alerte, « Appliquer » attend une case cochée. Appliquer passe par l'historique (Ctrl+Z). Serveur de démo : texte mis en majuscules (prévisible pour les tests), ou Claude si `ANTHROPIC_API_KEY` est donnée, avec FORMAT.md en consigne système. Écarté : appel direct à un modèle depuis le navigateur (clé exposée).
- 2026-11-12 — Phase 10 : document de démo qui montre chaque type (photos de démo générées dans `dev/demo-media/`, servies en repli de `/media/`) ; les essais partent de leur propre document. Accessibilité : `aria-label` sur chaque bouton à icône et chaque champ, focus visible, Ctrl+B / I / U et Alt+F10 (barre de mise en forme), poignée déplaçable aux flèches ; un parcours de check.mjs ajoute, écrit, met en forme, déplace et supprime sans souris.
- 2026-11-13 — Evol2, carte : retour de la colonne de droite (monter / poignée / descendre), trois boutons ronds à droite du type (menu « ⋯ », plein écran, supprimer avec confirmation). Règle : une action = un seul endroit ; le menu « ⋯ » ne garde que dupliquer, copier, coller au-dessus, coller dessous, IA (« couper » = copier puis supprimer). Boutons de la colonne : 44 × 32 px (trois boutons empilés dans une carte de titre sans la rallonger ; 24 px est le minimum WCAG 2.5.8). Remplace la décision de phase 4 (tout dans « ⋯ »).
- 2026-11-13 — Evol2, aération : la pastille « Insérer » / « Fusionner » est à 12 px des cartes (avant : collée, intervalles en marge négative). Un bouton « Insérer » avant le premier bloc. Cartes H2 : bordure noire de 2 px, H3 : 1 px, pour voir les sections.
- 2026-11-13 — Evol2, listes à plusieurs niveaux : sous-liste indentée de la largeur de la puce du parent (2 espaces sous `- `, 3 sous `1. `), comme CommonMark. Tab descend un élément sous le précédent, Maj+Tab le remonte (ses suivants deviennent ses enfants) ; quand rien n'est possible, Tab garde son rôle de navigation (pas de piège clavier). Une indentation hors règle reste lue sans perte (texte). Remplace « liste à un seul niveau » (phase 3).
- 2026-11-13 — Evol2, barre de mise en forme : sous-menu « presse-papiers » (copier, couper, coller le texte sélectionné, en texte simple, presse-papiers du système avec copie interne en secours). Bouton « Effacer la mise en forme » retiré : chaque style s'enlève par son propre bouton (une action = une façon), et la barre tient sur une ligne de 8 boutons de 44 px à 375 px.
- 2026-11-13 — Evol2, bloc HTML : le code seul par défaut, un bouton œil à côté du type bascule vers l'aperçu filtré (au lieu de code et aperçu côte à côte). Mécanisme générique : `tools(b, view)` et `data-view` sur la carte, réutilisable par d'autres types.
- 2026-11-13 — Evol2, plein écran reconstruit : le plein écran du navigateur était demandé sur la page (`document.documentElement`), qui entre alors dans la couche supérieure au-dessus du dialogue. Il est maintenant demandé sur un conteneur à l'intérieur du dialogue (Chrome refuse un `<dialog>` lui-même : « Dialog elements are invalid ») ; sortir de l'un ferme l'autre. Un bloc en plein écran est redessiné seul, sans habillage de carte (surface d'écriture, texte plus grand) ; sa carte perd `data-id` le temps de l'édition. Testé par un vrai clic (geste de l'utilisateur) à 1280 px.
- 2026-11-13 — Largeur : l'éditeur prend la largeur de son conteneur ; la colonne de texte est limitée par `--bq-width` (option `width`, 48rem par défaut). En plein écran, un bouton fait le tour de trois largeurs (40rem, 48rem, 100 %). Écarté : `max-w-3xl` en dur.
- 2026-11-13 — Titre du document facultatif (option `title`, absente par défaut) : l'éditeur peut ne remplir qu'une partie d'une page, il n'impose pas de titre. Sans elle, l'en-tête peut porter un libellé fixe de l'hôte (`label`) et le frontmatter est gardé tel quel. Remplace « titre et icône toujours dans l'en-tête » (phase 4).
- 2026-11-13 — Menus d'actions (« ⋯ » du bloc et de l'en-tête) sans ligne de titre ni bouton Fermer : chaque ligne se suffit, on ferme par le fond, Échap ou un choix ; le nom reste dans `aria-label`. Les feuilles à contenu (ajout, suppression, emoji, IA) gardent leur titre.
- 2026-11-13 — Plus de plein écran du navigateur (`requestFullscreen`) : le navigateur affiche toujours son message « Pour quitter le plein écran… », impossible à masquer, gênant pour écrire. Le plein écran est le seul `<dialog>` qui couvre la fenêtre (le mécanisme principal de la phase 5). Coût accepté : la barre d'adresse du téléphone reste visible.
- 2026-11-13 — Sélecteur d'emoji : sur écran tactile (`pointer: coarse`), aucun champ ne garde le focus à l'ouverture, le clavier se ferme et ne recouvre pas la grille ; la recherche reste à un toucher. À la souris, la recherche prend le focus.
- 2026-11-13 — Carrousel : une photo à la fois, flèches sur les côtés et puces dessous, sans barre de défilement. Le HTML publié porte les boutons cachés (`hidden`) ; `blockquilt-content.js` (facultatif, sans dépendance) les montre et les relie, et le noyau reste sans DOM. Sans ce script, la piste défile au doigt. Remplace « carrousel sans JavaScript, points décoratifs » (phase 7).
- 2026-11-13 — Bloc H1 (`# Titre`) dans le contenu : le titre n'est plus imposé dans l'en-tête, il peut être un bloc. Au rendu, le `title` du frontmatter ne devient un `<h1>` que si le corps n'en a pas (jamais deux `<h1>`). Remplace « `#` interdit dans le corps » (phase 3).
- 2026-11-13 — Texte en grand T1 / T2 / T3 : taille d'un H1 / H2 / H3 sans la sémantique d'un titre (accroche, chiffre clé) : `:::t1` … `:::`, rendu `<div class="bq-t1"><p>…</p></div>`, hors du plan de la page et des ancres. Convertibles avec les autres types texte. Écarté : `# Titre {.t1}` (attributs : pas du Markdown courant, mal relu par les IA et les autres outils).
- 2026-11-13 — Éditeur générique, sans notion d'« hôte » : option `label` retirée (ajoutée sur une mauvaise lecture de la demande) ; sans `title`, l'en-tête ne porte que les actions. Le titre d'un contenu se met dans le contenu (bloc H1). Code, CSS, README et démo ne parlent plus d'« hôte ».
